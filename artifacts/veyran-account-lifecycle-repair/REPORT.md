# VeyraN iOS/iPadOS account lifecycle repair — 2026-09-28

Release candidate work on `test`. This report supersedes account lifecycle observations for broken iPhone/iPad `3.4.16 (18)`; older migration/Mac evidence remains historical. Physical-device closure is pending. No `main` merge or App Store production release is authorized.

Notesnook Auth, Sync, Billing or hosted theme dependency reintroduced: **NO**. VeyraN remains the production account/service owner; no production server changes were made for this repair.

## Root cause

Commit `ecfcaa732` removed the post-signup PayWall route together with commercial UI. That screen had owned the final transition to the application. Registration could commit a valid encrypted account and return successfully while Signup retained its loading/current-step state and never navigated. The removed commercial screen had also coupled unrelated lifecycle completion to product metadata.

Settings rendered account management only when the mobile `user` store was hydrated. The incomplete signup/restore transition could leave it empty; the signed-out Account group then exposed only local deletion. This was an account-state visibility defect, not a subscription gate requiring a restored plan. The new signed-in and signed-out Account groups derive solely from cached account/session state.

Live Release testing also exposed a render loop in the restored session-status row: returning a fresh object from its hook retriggered SectionItem's derived-state effect. Native diagnostic counters exceeded 1,000 renders in about 1.5 seconds and the JavaScript thread exceeded 100% CPU, starving logout promises and timers. Memoizing the two status values reduced the measured process load to about 0.5%; backed-up logout then completed. A regression test checks reference stability across unrelated renders and correct updates on actual session changes. Temporary renderer/stage instrumentation was removed before the final native build.

## Account lifecycle

Registration and login share a verified completion bridge. Core proves the committed user, token scope, encryption keys, VeyraN affinity, device, and checkpoint before mobile publishes identity/profile, persists onboarding/session settings, enters Library, and starts normal encrypted Sync. Sync availability does not turn an otherwise valid offline-capable local profile into perpetual onboarding.

Auth/MFA/password stages follow granted token scope. Retry reuses the remotely created account and wrapped keyset; it does not repeat a successful registration POST. A presentation deadline replaces indefinite progress with localized recovery actions and cannot force app entry or race the still-running operation. HTTP deadlines include response body parsing.

Restart hydrates cached identity from local proof. Expired access with an existing refresh credential remains a normal session state. Narrow interrupted-signup recovery requires a descriptor proving a fresh, empty, VeyraN-owned profile and the same verified account/configuration; unknown/legacy data and existing account records remain blocked. The descriptor contains no password, token, or encryption keys. After a process interruption, normal login can finish only this proven account's missing key initialization.

## Settings and local data

Authenticated Settings shows VeyraN Account, email, session/setup state, existing safe account/Sync actions, and Sign out independently of plan or subscription. Signed-out Settings offers Sign in to VeyraN. Delete local data appears separately under Data with the existing confirmation dialog and a persisted-user recheck. It clears only the deliberate existing local profile; it does not call remote account deletion. Unsupported password/email changes and remote deletion are omitted; destructive no-key reset stays disabled.

Sign out retains the existing security model: revoke/unregister where possible, remove the local encrypted cache/settings, then return to Login. Its native confirmation explicitly explains those consequences. The preferred action saves a full backup. Unsynced or quarantined data requires a completed backup with locally required attachments; skipped/concurrent/failed/partial exports cannot satisfy the gate. Progress cannot be hidden. A writer barrier and final mutation guard protect backup/reset against changes while signing out. Cleanup must settle before another account operation starts.

The schema-reset view borrows the owning database driver without owning its initialization/destruction. An injected migration failure cannot close the shared database. Logout clears the monograph memory cache after schema reset without issuing a redundant SQL deletion inside the export barrier. The real encrypted SQLite roundtrip test now executes logout inside the same write barrier used by mobile.

## Safety and rollback

No encryption-format, editor-schema, standalone-Task architecture, native identity, App Group, or Keychain-group changes. No production server changes. Unknown/foreign affinity cannot be relabeled; rollback/recovery markers are retained where restoration cannot be verified. An expired partial signup may leave a harmless remote device record rather than blocking safe local recovery. If remote revocation succeeds before a later local safety refusal, local notes/keys remain intact but the revoked server token cannot be restored.

Rollback of this beta is to previous build 18 for installation, with its known account regressions. Source rollback must preserve data-safety/affinity policies; do not re-enable upstream cloud or unsafe credential mutation paths. Full backups are external artifacts and must be retained before any deliberate local-cache reset.
