## September 25 iOS Task widget regression — build 3.4.16 (15)

A physical iPhone running the current VeyraN TestFlight build showed the Tasks/Reminders widget without expected Task rows while the main app still displayed its Tasks. The code-level root cause is a day-boundary cache mismatch: the app's v3 writer only serialized Tasks scheduled on or before the snapshot's generation day, while the Widget extension rejected the entire file on the next local day and explicitly inserted an unavailable midnight timeline entry. Consequently, an app that remained closed across midnight lost all previously cached overdue rows, and Tasks that became due that day were absent from the file. A second physical-device timing defect let the 250 ms Task update debounce be suspended if the user left the app immediately after saving. Task persistence, Reminder projection, the `settings` mutation event, App Group identifiers, and `ReminderWidget` kind all matched and were not the break.

The fix keeps a bounded derived cache of incomplete scheduled Tasks, including future Reminders, and an optional date-count map for accurate Today/overdue badge counts. The production Widget decoder filters that cache by the current local calendar day, carries the available snapshot through midnight, and accepts the existing v3 format without the new optional field. A local DST offset change no longer invalidates wall-calendar schedules; a timezone change with a different current UTC offset still asks the user to open VeyraN for a fresh projection, while equivalent IANA aliases are accepted. The main app flushes pending Task snapshot writes when leaving the foreground under an iOS background task, and a privacy transition clears the old snapshot before immediately writing the App Lock redacted representation. Decode/read failures now emit safe reason codes without Task content. Snapshot writes remain atomic in the same App Group file; the encrypted Task domain remains authoritative.

Host, Widget, and Make Note source/compiled `appGroupId` and signed build-15 archive entitlements all agree on `group.com.ozel0t.note.notesnookpencil`. Both writer and reader use `reminder-widget-snapshot.json`; both reload and Widget declaration use `ReminderWidget`. The on-disk format remains schema v3, with additive optional `upcomingCounts` in the Swift decoder. Widget Task/complete/new links and the pending completion queue remain unchanged. The quick-add, completion-intent, Task notification, and alarm tests were included in focused validation.

Claude read-only architecture, diff, security, migration, and final reviews were completed. The diff review led to fixing the stale debounce handle, protecting background writes with the existing iOS background-task API, and adding App Lock transition coverage. The final review identified two physical-device risks: an iOS background time budget under memory pressure and a possibly missing App Group grant in distribution provisioning. The native writer already uses `Data.write(..., .atomic)`; the actual exported build-15 IPA's host, Widget, and Make Note embedded provisioning profiles were decoded and each grants the same App Group to the respective App ID. Runtime delivery under a signed physical TestFlight install remains unverified until a new build is installed; the fix must not be called physically validated from simulator results alone. The final review's possible badge double count was checked against the production builder's `date <= today` exclusion and the contract test's generation-day count.

Validation: 50 focused core Task tests and 42 focused mobile widget/link/completion/notification/alarm tests passed. A new persisted-domain contract creates `Widget Regression Test`, writes it through the real Task domain, serializes with the production TypeScript builder, decodes with the production Swift Widget decoder, then completes it and verifies the row disappears. Additional cross-language cases cover date-only, timed, overdue, recurring, Urgent, migrated, unscheduled, App Lock, old v3, midnight, DST, and more than 64 cached rows. Mobile TypeScript, `git diff --check`, Swift codec typecheck, and project plist lint passed. Release Xcode 27 built the host, Widget, and Make Note extension for ARM64 iOS Simulator; all three binaries are arm64. The final incremental build after the last source edits also passed. An isolated iPhone 18 Pro simulator installed and launched the app, but it was at first-run onboarding; the actual Home Screen Widget interaction was not exercised there. A signed physical-device/widget interaction has not yet been rerun. This fix requires a new TestFlight build for physical validation, but no build was uploaded during this investigation.

## Important history and editor boundary

The earlier Todo Widget approach stored tasks inside the Notes editor and caused a black-editor regression. It was rolled back. This implementation has an independent Task domain. It does not use Note IDs, Note bodies, TipTap nodes, ProseMirror positions, or editor bridge actions. Navigation and old Reminder affordances can open Task screens, but editor internals remain untouched. The ARM64 libsodium XCFramework remains in use; no simulator x86_64 exclusion or Rosetta workaround was introduced.

## Implemented architecture

`packages/core/src/collections/tasks.ts` owns Task and List records, stable IDs, validation, smart queries, RRULE recurrence, completion history, and migration. Each record is a versioned JSON `settingitem` carrier in the existing encrypted sync and backup path. The unified Reminder schedule uses local calendar strings (`YYYY-MM-DD`) and optional wall times (`HH:mm`); legacy due and reminder fields remain for compatibility. The Task record is authoritative. The official Web App ignores fork Task settings; no bidirectional legacy Reminder projection exists. Normal Notes, Notebooks, attachments, login, crypto, and wire item types are unchanged. Details and compatibility boundaries are in `docs/tasks-architecture.md`.

Legacy Reminders migrate to a deterministic default List and deterministic Task ID. The Task is durably written while the source Reminder remains active for older clients in a staged rollout. Updated iOS and desktop clients suppress the converted source locally in their Reminder UI and alert planners. Task tombstones keep the suppression after Task deletion. Description and snooze time are preserved; unsupported recurrence modes remain in the legacy store. A stale recurring Reminder rolls forward to its first scheduled occurrence at or after migration while retaining its original series anchor; a future snooze remains active. The migration is versioned, retryable, and invoked at startup, after sync, and after backup import. Completed recurring occurrences remain in history; the next occurrence uses a deterministic schedule-relative ID and is reconciled after interruption. Persisted completion wall date/time makes late-completion catch-up stable after cross-timezone sync.

iPhone and iPad have standalone Task navigation, Today/Scheduled/All/Flagged/Completed, custom Lists, quick add, detail editing, completion, priority, flag, unified Reminder schedule, Urgent, Favorites, List appearance, and recurrence. iPad uses its own two-pane layout. macOS uses the existing Electron app and renderer, with matching Task navigation, Lists, editor, and actions. It has an in-memory main-process notification schedule so notifications continue while the app is running with its last window closed. With App Lock enabled, desktop and browser Task alerts use a generic localized title; an already scheduled desktop payload is redacted on lock changes and at locked renderer startup.

The iOS WidgetKit extension reads a small Task snapshot from the App Group. Completion opens the app through a validated Task link, persists a narrow account-scoped intent in MMKV, waits for database readiness and App Lock release, and applies the idempotent Task operation. Queued intents expire after 24 hours. App Lock replaces the snapshot with a redacted privacy placeholder containing no Task IDs or titles; logout and account changes clear it. The extension never accesses the encrypted database or Notes editor.

## Known validation and product limits

- A fully quit macOS app has no OS-level persistent Task reminder delivery. Notifications work while the Electron process remains running, including after its last window closes.
- The Today widget shows a refresh prompt after local midnight or timezone/UTC-offset change until the main app writes a new snapshot. It does not show a stale previous-day list.
- Live server multi-device sync and an authenticated official Web App session were not available for end-to-end testing. Two local encrypted databases passed collector/receiver sync coverage. The official Web App is expected to ignore fork-only settings based on the unchanged wire type and static compatibility audit.
- Generic per-record last-write-wins sync still applies to simultaneous edits of the same Task. Field-level conflict merging is not implemented.
- Favorites order and List appearance also use per-record last-write-wins sync; concurrent offline edits to the same record can overwrite one another.
- Older clients retain and can still alert on a migrated source Reminder; this is intentional staged-rollout compatibility. Changes made to that source on an older client do not update the already imported Task, and the Task editor warns about this one-way cutover. Completion on a new client does not silence an older client's source Reminder. After all clients upgrade, the retained source may be retired in a later migration.
- Notification permission and delivery smoke on a physical device remains unverified; planner tests and ARM64 native builds pass.
- The older Duplicate Note E2E title assertion does not match the current generated-title behavior. It is outside this Task subsystem; Note content save/reopen, history, and duplication creation were observed on the simulator, but the broad Note E2E suite is not green.
