## MANDATORY exhaustive registry test
At execution time, Codex shall generate a machine-readable inventory by enumerating:
- `getAllTools()` and `getDefaultPresets()` in the fork and current public upstream revision, including conditional tools, Mac-only additions, required extensions/storage callbacks, menu actions and keybindings.
- `getInsertMenuItems()` and context-specific link/image/table/embed/attachment actions.
- Every editor action route: Mac native Format, web toolbar, `Aa`, `+`, note overflow, context menu, keyboard shortcut, customizable menu; map exact paths per iPhone, iPad, Mac.
- Settings definitions (`settings-data.tsx` plus Mac-only settings), rendering conditions, getter/setter, target store and consumers. Mark dead, duplicated, erroneously present or ignored settings. A setting is not VERIFIED until toggling it changes actual runtime UI/behavior and persists as appropriate.
- Present/absent states of function flags, subscriptions/entitlements, 2FA, sync, vault, backup, security, accessibility and offline behavior. Never bypass feature gates in order to make UI appear to work.

## Completion gate
NO feature is considered restored based on the existence of a function in code. It must be discoverable from the real UI, invoke the correct action, preserve selection/data and pass a platform-specific runtime test. If a screenshot suggests regression but cannot be reproduced, document it as unverified rather than claim a fix.
